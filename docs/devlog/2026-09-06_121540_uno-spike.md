# Uno Platform spike

The player wanted to investigate Uno Platform because losing Linux support made
the MAUI Blazor Hybrid direction uncomfortable.

Created branch `uno_spike`, installed `Uno.Templates` 6.7.22 and generated a
blank desktop-only Uno app under `src/StoryWeaver.Uno`. The selected template
target was `net10.0-desktop` with `SimpleTheme` and `SkiaRenderer`, which is the
Uno desktop path documented for Windows, Linux and macOS.

Replaced the generated hello page with a static StoryWeaver-shaped shell:
narration left, player input row, explorer/status right. It intentionally does
not call gameplay code yet; the point is proving the desktop UI stack and project
shape, not moving policy into a client.

The Uno project built directly. After adding it to `StoryWeaver.sln`, the root
solution build initially failed because `Uno.Sdk` was only pinned in the nested
template `global.json`. Added a root `global.json` pinning `Uno.Sdk` 6.7.22, then
`dotnet build StoryWeaver.sln` passed with zero warnings and zero errors. A
Windows launch smoke also passed: the app started and stayed
alive for 8 seconds before being stopped.

Uno is now the leading UI candidate under spike, not a locked decision. The next
meaningful check is a Linux desktop build/run on a Linux machine or CI runner.

Follow-up the same day: WSL2 Ubuntu 26.04 was available. Installed .NET SDK
10.0.400 into `/home/pavel/.dotnet` and built `StoryWeaver.sln` from WSL with
GUI environment variables unset. The Linux build passed with one warning and
zero errors. The warning came from Uno resource language detection while .NET
ran in invariant globalization mode because ICU is missing in the WSL distro.

Linux GUI launch remains unverified. WSLg shows a Windows Remote Desktop ActiveX
popup about `rdclientax.dll`, so the next run check needs either fixed WSLg or a
different Linux desktop/VM. `C:\Program Files\WSL\rdclientax.dll` exists locally,
so this is not a simple missing-file case.

Follow-up: opening the solution in Visual Studio 2022 failed because the IDE's
MSBuild is 17.14, while .NET SDK 10.0.400 requires MSBuild 18.0 or newer. The
CLI build worked because `dotnet build` uses the SDK's bundled MSBuild. Retargeted
the Uno spike to `net9.0-desktop`, pinned .NET SDK 9.0.314 in both `global.json`
files, and verified restore/build through Visual Studio's MSBuild path. The
retargeted `net9.0-desktop` app also passed the Windows launch smoke.

Follow-up: the player chose to park the Linux question until there is a working
Linux environment. Uno's Linux support remains part of why it is being considered,
but the spike now continues on Windows first.
