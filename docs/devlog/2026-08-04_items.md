# Devlog — the fifth entity type

**Date:** 2026-08-04
**Scope:** `Item`, four deltas, and a false-canon merge that stopped happening

---

## What shipped

`Item` in Core, four deltas mirroring the character set, validator rules, both context
renderings, an extraction prompt rule, and four self-tests. Ids now span five namespaces.

The deltas are deliberately the character set's shape, because the extractor already handles
that at 100%:

| item delta | mirrors |
|---|---|
| `item_introduced` | `character_introduced` |
| `item_moved` | `character_moved` |
| `item_renamed` | `character_renamed` |
| `item_status_changed` | `status_changed` |

## Results

```
object-described        7/7 items-as-characters  ->  0/7        (1/7 residual description-fact)
scenery-vs-object       forbidden 0.00, item captured with the right holder 7/7
wrong-object-acted-on   0/14  ->  14/14 required, forbidden 0.00
full scored set, 9      100% required, forbidden 0.00, 50/50 clean (pinned)
--selftest              4 new item checks
end to end              one turn: item introduced, moved to the player, visible in context
```

The headline is the third line. **The false-canon merge no longer happens.** With two objects
present and one ground in a mortar, the capstone was never once recorded as the thing that
changed, and the pale chunks were correct every run.

## The invariant that does the work

An item is **in a location or held by a character, never both and never neither.**

Neither is how an object silently stops existing while remaining in canon. Both is how one
object ends up recorded in two places — which is the shape of the merge that produced false
canon in play. One shared `Placement` check covers introduction and movement, so the invariant
cannot hold at one door and not the other, and `DeltaApplier` assigns *both* fields from every
move, so picking something up clears where it was rather than adding to it.

Three self-tests hold it.

## What measurement caught, twice

**The scenario was measuring the validator, not the model.** The first run of
`wrong-object-acted-on` with items available produced seven rejections — the model emitted
`item_status_changed` against ids that did not exist, because the scenario's seed had no items.
That is correct validator behaviour and a useless measurement. The seed now carries both
objects, which is the state play was actually in.

Buried in those rejections was the real finding: **runs 3 and 5 named the capstone.** The merge,
reproduced at last, and only visible because `--show-deltas` prints rejected proposals.

**Then my scoring rule was wrong for the third time.** With the seed fixed, required scored
7/14 — the model had answered `item_renamed pale-chunks -> coarse glittering powder` where the
rule demanded `item_status_changed`. Both are defensible; the chunks genuinely became something
else. Rewritten to accept either, it is 14/14.

That is the same mistake as the two-stage-entry movement rule and the Sera fact rule: **a rule
must target the world the turn produces, not the route taken to it.** Written down twice
already and made again, which suggests the lesson does not transfer by being recorded — the
check that works is reading the deltas behind a failing rule before believing it.

## Deliberately not built

Quantity, item properties, containers, and crafting. Grinding a stone is
`item_status_changed`; powder plus salt becoming paste is a *system*, not a delta, and guessing
at it would have doubled the schema to serve something no measurement demanded yet. Stats
belong with dice-resolved checks.

## The known cost

Loose items are listed in the scene for the narrator, which is right — an object left on a
counter is part of what is there, and one that vanished from view while still being in canon is
the quiet inconsistency this architecture exists to prevent.

It also means **a room accumulating dropped objects grows the context block every turn.** That
is the budgeting problem already deferred for lore, now with a second contributor. Worth
measuring in a real session before it is worth solving.

## Next

The item type does not fix the contradictory claims about where the stone went — that is
`source` on facts, four sightings and counting. And a third play session is what would confirm
the object-fact share actually falls; 60% of one session's facts mentioned objects, and that
number should now drop.
