# Uno play layout

The Windows Uno spike now looks more like the first play surface and less like a
diagnostic preview. The layout is still deliberately plain, but the roles are
clearer: a header names the app and session state, a status pill gives the short
answer, the central pane is the transcript/opening, the bottom bar is always the
player command surface, and the side rail holds scene/session details plus
debug actions.

The code-behind still follows the thin-client rule. Session opening remains
`SessionOpener.OpenAsync`; turns remain `StorySession.TakeTurnAsync`; canon
refresh remains `StorySession.UpdateStateAsync`; the UI only renders the result
and toggles controls while a turn is running.

Two follow-up UI items came out of this pass. First, State and Prose are useful,
but they currently replace the opening text rather than being real modes with a
clear way back to the active transcript. Second, the status pill carries the
right words but no visual state language yet, so ready/thinking/refused/failed
states still look too similar.

Verification: `dotnet build StoryWeaver.sln` passed with zero warnings and zero
errors. A short Windows desktop launch stayed alive; the only startup output was
Uno's existing Win32 text-scale registry warning.
